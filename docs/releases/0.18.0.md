# DEDAL Core 0.18.0

_Date: 2026-09-14_

## Summary

Begins the post-expansion hardening campaign with executable GitHub mutation-mode guardrails, complete skill-consolidation classification, and a machine-readable continuity checkpoint contract.

## Added

- `runtime/github_mutation_guard.py` and `runtime/github-mutation-policy.json` for fail-closed mutation-mode checks suitable for host/tool-dispatcher integration.
- `evals/github-mutation-guard/contract-v1.json` with positive and negative transition cases.
- `scripts/validate_runtime_contracts.py` and a dedicated `Runtime Contracts` GitHub Actions workflow.
- `state/skill-consolidation.json` covering every live skill entrypoint with KEEP / TUNE / MERGE / REMOVE / NEEDS_EVIDENCE.
- `state/checkpoint.schema.json` plus `state/current-checkpoint.json` for executable continuity state.

## Changed

- GitHub mutation preflight now distinguishes executable guard availability from actual provider-tool interception.
- Consolidation CE-01 records that a guard contract now exists while host integration remains pending.
- Skill Acquisition is classified `TUNE`: keep it available, but do not let the completed expansion roadmap trigger another growth wave by default.
- The human-readable continuity checkpoint now points to the machine-readable checkpoint and records residual enforcement risk explicitly.

## Evidence maturity

This release adds **contract-level enforcement machinery** and CI validation. It does not claim universal platform-level prevention because the public Core cannot intercept native GitHub provider tools unless the host routes mutations through the guard.

No new global efficiency percentage is claimed. Existing regressions, including the v0.15 wrong-tool mutation failure, remain evidence rather than being erased from the record.
