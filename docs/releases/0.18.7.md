# 0.18.7 — Delegation authority hardening

## Summary

DEDAL now treats multi-agent delegation as an authority-attenuation boundary rather than an implicit copy of the parent agent's capabilities.

## Added

- executable delegation-authority contract;
- deterministic validator wired into Runtime Contracts CI;
- explicit parent-to-child authority attenuation rules;
- provenance and escalation requirements for delegated work;
- handoff-vs-authority-transfer distinction.

## Core rules

- A child may receive only a subset of the parent's currently authorized tools, modes, resource scopes, and task intent.
- Delegation cannot manufacture authority the parent does not hold.
- A handoff may transfer control of the workflow, but does not automatically expand or recreate tool authority.
- Child re-delegation is allowed only when explicitly permitted and remains recursively bounded by the original grant.
- Missing authority causes escalation back to the parent/owner; the child must not self-authorize.
- Prefer brokered/scoped capabilities over copying ambient credentials into workers.
- Delegated results must return compact provenance, evidence references, unresolved uncertainty, and any blocked/escalated actions needed for acceptance.
- Child/model claims remain candidate state until the owning workflow verifies them appropriately.

## Evidence level

This release provides design and executable contract validation. It does not prove real-task outcome improvement or universal host enforcement.

## External influences

Adapted from current OpenAI handoff/orchestration guidance, Anthropic containment guidance, and OWASP agentic identity/authorization and confused-deputy guidance. No external runtime was installed or vendored.
