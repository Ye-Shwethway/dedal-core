# DEDAL Core 0.19.0

## Foundation architecture: persistent cognitive runtime

v0.19.0 changes DEDAL's operating model from potentially ambiguous skill activation into an explicit layered intelligence architecture.

DEDAL is now defined as one coherent persistent intelligence with:

1. a Constitutional Kernel that remains authoritative;
2. a compact always-active Cognitive Runtime;
3. a run/subgoal-scoped Capability Composer;
4. progressively disclosed specialist skills and separately verified execution surfaces.

## Why this change

A named skill being loaded must not make the rest of DEDAL's universal operating intelligence disappear. At the same time, loading every specialist skill on every task would waste context and create instruction collisions.

The new model is:

`always-on brain + on-demand faculties`

rather than either:

- `one active skill replaces everything else`, or
- `all skills stay loaded all the time`.

## Capability roles

The active subgoal can assign:

- `RUNTIME` — compact always-active invariants;
- `PRIMARY` — current specialist intent owner;
- `SUPPORTING` — distinct necessary supporting specialist;
- `EXECUTION` — current tool/plugin/MCP/native action surface;
- `DORMANT` — known capability not loaded into working context.

Explicit aliases/named-skill requests select a strong PRIMARY route without disabling Runtime or blocking genuinely necessary support.

## Progressive disclosure

Capability metadata can remain discoverable while full skill bodies, references, scripts, schemas, and examples load only when required. Tools are selected and authorized separately from skills.

## Research basis

The architecture was developed after reviewing and pinning current public patterns including:

- `agentskills/agentskills` at `69ef37e9424c0a7ea9dd2293b559e43ec8176379` — metadata/instruction/resource progressive disclosure;
- `langchain-ai/deepagents` at `c08cae693e0036fcd45d979a7dfa3a7e306a0515` — always-on middleware/harness with dynamically composed skills, memory, subagents, permissions, and tool surfaces;
- current OpenAI Agents SDK documentation — shared run context, dynamic tool/handoff enablement, deferred tool discovery, and manager/specialist composition;
- recent 2026 Agent Operating System research separating control/governance responsibilities from runtime/capability coordination.

No external framework/runtime dependency was added.

## Executable validation

Added:

- `runtime/capability-composition-policy.json`
- `evals/capability-composition/contract-v1.json`
- `scripts/validate_capability_composition_contract.py`

The contract covers image-workflow composition, explicit named-skill activation, missing-runtime rejection, load-all rejection, agent/security/research composition, domain+generic support, runtime-only simple tasks, and explicit-alias ownership preservation.

## Kernel/boot changes

Added `kernel/COGNITIVE_RUNTIME.md` to minimal boot and refined Kernel/Boot semantics so full specialist skills remain progressively loaded rather than globally active.

## Evidence boundary

This release has architecture rationale and executable contract validation. It does **not** yet prove representative real-task gains in intelligence, context efficiency, or routing quality. Outcome evidence must accumulate from ordinary work.
