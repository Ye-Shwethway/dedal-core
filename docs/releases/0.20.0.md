# DEDAL Core 0.20.0

## Quality Engineering faculty

DEDAL now has an active `quality-engineering` faculty for independent product-quality verification.

### Why

Software Development already owned implementation and developer-facing tests, Interface Design owned UX/UI direction, and Release Engineering owned artifact/deploy lifecycle. A recurring gap remained around independent acceptance truth, risk-weighted test strategy, exploratory/E2E/regression evidence, failure characterization, and readiness recommendations.

### What changed

- added `skills/quality-engineering/SKILL.md` with progressive references;
- defined independent QA ownership boundaries against Software Development, Interface Design, Release Engineering, and Security Engineering;
- kept Playwright/browser/mobile/API tooling as execution surfaces rather than faculty identity;
- added routing contract cases for implementation vs independent QA vs design/security/release responsibilities;
- added CI validation for the new routing contract;
- updated the capability-gap map: Quality Engineering promoted, Cloudflare Platform becomes the next deep-audit candidate;
- recorded source provenance from current Playwright documentation and pinned community QA corpora.

### Durable principles

- quality evidence starts from claims and risk, not test count;
- prefer user-visible/public-contract oracles and isolated reproducible checks;
- blind reruns do not erase flakes;
- automated accessibility and visual checks are partial evidence and must not be overstated;
- readiness verdicts expose verified scope, uncovered risk, and evidence limits;
- QA recommends readiness; release promotion remains a separate authority/lifecycle concern.

No third-party QA runtime or scripts were installed as a Core dependency.
