# DEDAL Core 0.21.0

## Cloudflare Platform promotion

Promotes `cloudflare-platform` to an active top-level DEDAL faculty after a first-party deep audit of `cloudflare/skills` and current Cloudflare developer documentation.

### Why it exists

Repeated Creator workflows span Workers, Pages, D1, R2, Access, Tunnel, DNS/network routing, Wrangler, observability, and agent infrastructure. The reusable gap is not generic coding; it is Cloudflare-specific product selection/composition, binding/environment semantics, edge/network topology, and provider-native operational evidence.

### Boundary

Cloudflare Platform does not replace:

- Software Development for application implementation/debugging;
- Release Engineering for promotion/provenance/rollback;
- Security Engineering for trust/access policy and threat reasoning;
- Data Operations or a future Database Engineering owner for data correctness/database semantics;
- Quality Engineering for independent acceptance/readiness;
- Agent Engineering for agent/harness design.

### Freshness policy

Drift-sensitive Cloudflare facts — product availability, beta/stable status, limits, pricing, CLI/API syntax, plan requirements, compatibility, and migration recommendations — must be verified from current official Cloudflare documentation when material. Core retains durable platform reasoning, not a frozen product manual.
