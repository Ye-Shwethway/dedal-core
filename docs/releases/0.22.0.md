# DEDAL Core v0.22.0

## Database Engineering faculty

Database Engineering is promoted to an active top-level faculty after a reference-first deep audit of PostgreSQL, SQLite, Neon/Postgres, and Supabase guidance.

It owns database semantics:
- schema invariants, keys, constraints, and data types;
- indexes/access paths and query-plan reasoning;
- transaction boundaries, isolation, locking, conflicts, and deadlocks;
- migration/backfill/compatibility and recovery semantics;
- connection/session/pooling behavior;
- engine-specific concurrency and operational tradeoffs.

It does **not** replace:
- Software Development for application/ORM implementation;
- Data Operations for record authority, reconciliation, deduplication, or staging;
- Cloudflare Platform for D1/Hyperdrive product/binding/provider semantics;
- Release Engineering for production promotion/rollback authority;
- Quality Engineering for independent readiness;
- Security Engineering for trust/access policy.

## Evidence discipline

- Index/performance changes require workload/query-plan evidence where feasible.
- ORM/schema compilation is not proof of database runtime correctness.
- Migration command success is not proof of safe production evolution.
- Schema rollback and data rollback are distinct claims.
- PostgreSQL and SQLite/D1 concurrency/locking semantics must not be interchanged.
- Engine-version/provider-specific facts are live-verified when material.
