# DEDAL Core 0.23.0 — Reliability Engineering

## Summary

Promotes `reliability-engineering` as a top-level DEDAL faculty after the Observability/SRE deep audit.

## Why

A distinct recurring ownership layer exists between implementation, QA, release promotion, provider/database semantics, and security: defining user-visible service health, choosing operational evidence, creating actionable alerting, responding to incidents, verifying recovery, and learning from failures.

## Added

- `skills/reliability-engineering/SKILL.md`
- progressive references for observability/service health and incidents/postmortems
- `skills/skill-acquisition/references/reliability-engineering-deep-audit-2026-09-14.md`
- executable reliability routing contract and validator

## Boundaries

- Release Engineering ships and rolls back releases; Reliability Engineering owns live service health and incident response.
- Software Development implements code/instrumentation; Reliability Engineering defines the operational questions/signals needed.
- Quality Engineering owns independent acceptance/readiness; Reliability Engineering owns production behavior.
- Security Engineering owns security policy/incidents; Reliability Engineering can support availability/telemetry during them.
- Cloudflare Platform and Database Engineering retain provider/engine semantics.
