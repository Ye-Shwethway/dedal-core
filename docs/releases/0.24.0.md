# DEDAL Core 0.24.0

## Infrastructure Engineering promotion and skill-wave close

Promotes `infrastructure-engineering` as a top-level faculty after an Infrastructure/IaC deep audit.

### Why

Infrastructure lifecycle work has a distinct recurring ownership layer: declarative configuration/state/live-resource reconciliation, plan/apply semantics, drift, imports/moves/refactors, provider/module lifecycle, destructive-change review, and partial-apply/state recovery. These concerns are not equivalent to application implementation, artifact release, provider product architecture, or live-service reliability.

### Boundaries

- Software Development owns application code.
- Release Engineering owns application artifact promotion and rollback mechanics.
- Reliability Engineering owns live service health and incidents.
- Cloudflare Platform owns Cloudflare product/platform semantics.
- Database Engineering owns database engine semantics.
- Security Engineering owns trust/credential/destructive-risk policy.
- Quality Engineering owns independent acceptance/readiness.

Terraform, OpenTofu, Packer and provider CLIs are execution/reference surfaces rather than the faculty identity.

### Durable rules

- configuration, state and live provider reality are distinct evidence views;
- speculative plan != applied change;
- apply success != healthy service;
- `auto-approve` != authority;
- direct state mutation is elevated recovery work, not an ordinary first-line fix;
- drift must be classified before reconciliation;
- provider/tool/version-specific facts remain live-doc-sensitive.

### Evidence

Audit sources include HashiCorp `agent-skills@c2d65dfe492f74d360d35b859b88932222470bd8`, current Terraform official plan/apply/state/drift guidance, and current OpenTofu plan/apply documentation.

### Campaign state

This closes the current proactive capability-expansion wave. Immediate high-value gaps have been classified or promoted. Mobile remains a reference pack, browser/computer automation remains an execution surface, and healthcare/clinical informatics remains later/high-bar. The next phase is ordinary-work outcome validation rather than continued skill expansion by default.
