# DEDAL Core 0.26.0 — YouTube Publishing Hardening

Date: 2026-09-16

## Why this release exists

The previously promoted YouTube Publishing faculty accumulated new representative live evidence after the v0.25.0 checkpoint. This release reconciles that evidence into durable Core contracts without duplicating the earlier upload/MCP promotion.

## Promoted live gates

- caption lifecycle: list, insert, readback, VTT download, update, delete, and restoration of the original state;
- thumbnail upload on an owned video;
- playlist-image first insert plus verified managed replacement;
- channel-banner upload/apply/readback and restoration from a recoverable full-resolution source.

## Hardening decisions

- Native `playlistImages.update` is not a production dependency after inconsistent `unexpectedPart` failures. Replace-style playlist media uses managed state, delete -> insert -> readback, and rollback.
- Existing unmanaged replacement state fails closed rather than being destroyed.
- Banner rollback state is the recoverable/full-resolution source, not merely a display-oriented `bannerExternalUrl`.
- Watermark set/unset remains exposed but is not promoted to a fully live-gated lifecycle because YouTube does not provide a reliable current-state read surface. Unmanaged watermark removal requires explicit Creator authority.
- Hard mutation diagnosis follows dedicated MCP -> bounded Gateway -> stage-aware D1 audit -> exact vendor error -> minimal patch -> one bounded retry -> readback.
- Vendor diagnostics may be retained only in bounded, secret-free form.

## Runtime/source identity

External live evidence for this hardening sequence reported Gateway `0.7.35`, while the checked-in Gateway source still identifies itself as `0.3.0`. The release records the verified behavior and the source-parity gap rather than pretending the public snapshot is current. The checked-in MCP source identifies itself as `0.1.0`; no newer exact deployed MCP version is canonized without independent evidence.

## Validation

`evals/youtube-publishing-hardening/contract-v1.json` plus `scripts/validate_youtube_publishing_hardening.py` cover required promotion cases, fail-closed replacement/watermark policy, diagnostic fields, and secret-exclusion rules. Runtime Contracts CI runs the validator.
