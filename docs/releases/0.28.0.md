# DEDAL Core 0.28.0 — Cloudflare Operational Hardening

Date: 2026-09-16

## Why this release exists

Repeated real Cloudflare maintenance exposed a gap between sound platform architecture guidance and reliable execution across connectors, aggregation layers, raw Worker source, multipart uploads, and ambiguous post-mutation read-back. The failure mode was operational rather than a need for another overlapping top-level Cloudflare faculty.

This release strengthens the existing `cloudflare-platform` skill with durable execution/recovery rules and executable contract coverage.

## Added

- `skills/cloudflare-platform/references/worker-deployment-and-connector-recovery.md`
- `evals/cloudflare-platform-operations/contract-v1.json`
- `scripts/validate_cloudflare_platform_operations.py`

## Changed

- Cloudflare operations now distinguish repository source, build artifacts, deployed Worker content, and sanitized public reconstructions until equivalence is proven.
- A newer live Worker must not be overwritten with stale repository source merely because repository access is easier.
- Connector read/discovery capability is no longer treated as proof of write-transport fidelity.
- Raw/multipart/module upload semantics are verified before production source writes; transport-wrapper defects should trigger an execution-surface change rather than application-code distortion.
- Automated native/direct/API/CLI paths are preferred before asking the Creator to edit production source manually, especially in mobile-constrained workflows.
- Mutations that may have committed before a transport/read-back failure require state verification before retry; bounded read-after-write retry is permitted for eventual consistency and unresolved outcomes remain explicit.
- Aggregated MCP use must preserve the remote MCP as the canonical semantic/tool-schema source unless migration is intentional.
- The YouTube hardening validator is decoupled from global Core checkpoint naming so cross-domain releases can advance without false validation failure.

## Capability-state policy

Cloudflare and integration-aggregation availability are recorded as `verify_per_session` rather than permanently assumed. Execution surfaces remain runtime facts, not durable guarantees.

## Validation

The new Cloudflare operations contract covers live-vs-repository source drift, connector serialization failures, large-source retrieval, eventual consistency, false-negative mutations, MCP aggregation, code-only Worker patches, and automation-first mobile operation.
