# DEDAL Core 0.29.0 — Private Operational Overlay Boundary

## Purpose

This release adds a public-safe contract for optional Library-only operational context that can improve cross-chat continuity without publishing Creator/project-specific facts.

## Added

- Optional private operational overlay discovery in the boot contract with manifest-first, task-relevant progressive disclosure.
- Explicit authority ordering: live connected services own current resource state; GitHub owns repository/code identity; the private overlay owns durable non-secret operational context only.
- Fail-closed privacy scanning for overlay paths or overlay manifests accidentally introduced into the public repository.
- Defense-in-depth `.gitignore` entries for conventional overlay paths.

## Safety boundary

The overlay may hold private but non-secret operational facts such as resource identifiers, aliases, niche/project context, lessons, and checkpoints. It is not a credential store. OAuth tokens, API keys, cookies, passwords, private keys, bearer tokens, and equivalent authentication material remain excluded.

## Portability

DEDAL Core remains correct and bootable without the private overlay. Overlay availability is host/session dependent and must not become a hidden dependency of public Core.
