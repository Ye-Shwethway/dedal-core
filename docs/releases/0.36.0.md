# DEDAL Core 0.36.0 — Generative Video Direction

## Summary

Core 0.36.0 separates generative motion direction from post-production editing. The new `generative-video-direction` faculty converts accepted narrative and visual state into provider-neutral Motion Shot Specs, reference-role plans, current provider execution contracts, generated takes, take QA, and targeted repair. The previous combined `video-production` implementation becomes canonical `video-post-production`, with legacy aliases preserved.

## Creative pipeline

`Story Weaver -> Visual Narrative Production -> Generative Video Direction -> Video Post-Production`

The pipeline is not strictly one-way: GVD can request a missing/corrected keyframe or geometry reference from Visual Narrative Production when that is the smallest reliable control improvement.

## Provider boundary

Veo, Seedance, Runway, Firefly, Kling, Luma and successor systems remain execution surfaces. Provider facts are volatile adapter knowledge and must be verified when material. Unsupported/unverified controls are represented as `unknown`, not guessed.

## External research policy

First-party docs and public skill repositories informed methodology and architecture only. DEDAL did not fork or copy third-party skill text/code; the new skill is a native rewrite preserving DEDAL authority, evidence, privacy, routing and evaluation conventions.

## Evidence status

Static contracts/routing/validators can establish architectural correctness. Representative provider runs are still required before claiming reduced retries, higher usable-take rate, or better final-video quality.
