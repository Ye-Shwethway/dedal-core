## GH-01 — Atomic multi-file mutation

**Result: FAIL, with safe recovery.**

Observed sequence:
1. A coherent benchmark tree/commit was prepared from the original HEAD.
2. Before the prepared commit was fast-forwarded, a direct checkpoint write advanced `main` to `925ce23b0287a94cb655110afc2e7d7f3a4c60ee`.
3. A second mistaken same-content `VERSION` direct write created `1fb722499c5a86ceb8228a628418aa39737a4065` with message `noop`.
4. The prepared mutation could no longer be fast-forwarded safely from its original parent.
5. DEDAL did not force the ref. It refreshed live HEAD, treated it as authoritative, rebuilt the benchmark tree from the new state, committed `b43b100702fd8f419a2c1d5b7cd5d54786719cc0`, and fast-forwarded `main` normally.

Why FAIL:
- the run mixed mutation paths;
- it produced avoidable intermediate commits;
- it repeated the exact class of failure Harness v1 was intended to prevent.

Positive recovery evidence:
- no force update;
- no history rewrite;
- no silent overwrite of newer state;
- final benchmark files were reconstructed from the live authoritative HEAD.

New regression lesson:
**A written transaction rule is insufficient if tool selection remains ambiguous during execution. Before any coherent multi-file mutation, DEDAL must lock the mutation mode for that work unit (`tree transaction` or `direct single-file write`) and reject switching modes unless reconciliation is explicitly required by an observed external state change.**
