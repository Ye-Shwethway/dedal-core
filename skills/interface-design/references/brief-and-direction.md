# Brief and Direction

## Read the room first

Infer from available evidence before inventing direction:
- surface/page kind and dominant user task;
- audience and trust expectations;
- explicit vibe/brand language and reference images/sites;
- existing assets, typography, colors, components, and product conventions;
- quiet constraints such as accessibility, regulation, localization, device class, or public-sector expectations.

If two plausible directions would lead to materially different work and evidence cannot resolve them, ask one high-value question. Otherwise state the working design read and proceed.

## Surface modes

**Persuade:** optimize comprehension, credibility, emotional signal, and action.

**Operate:** optimize scanability, state clarity, keyboard/touch behavior, error recovery, and task throughput.

**Read:** optimize structure, measure, hierarchy, navigation, contrast, and sustained reading comfort.

**Experience:** let the content/artifact dominate; use interface chrome only where it helps orientation or interaction.

## Design systems vs aesthetics

A design system is an implementation contract with components/tokens/behavior. An aesthetic is a visual direction. Do not confuse them.

When a project already uses a real system, preserve it unless replacement is part of the task. When choosing a new system, verify the actual package/version and project compatibility. When using aesthetic inspiration, describe it honestly and implement it with the project’s available primitives.

## Anti-default discipline

Avoid choosing a visual pattern merely because it is a common model default. Repeated card grids, generic gradients, glass effects, centered hero compositions, arbitrary motion, or fashionable typography are acceptable only when the brief supports them.

The correction is not to ban styles; it is to make every major choice traceable to the brief, audience, task, or existing product language.
