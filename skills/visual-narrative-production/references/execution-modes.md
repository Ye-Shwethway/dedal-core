# Visual execution modes

Use one compact card: mode, purpose, requested asset count/format, subject roster,
pixel references by role and subject, preserve/change, relevant spatial relations,
observed QA and acceptance state. Unchanged fields may be reused within a task.

## Select the required branch before generating

| Current work | Required additional references |
|---|---|
| Canonical subject or anchor | reference-hierarchy-and-canonical-locks.md; resolve current private subject policy and actual accepted pixels |
| Local edit | generation-edit-and-anchor-promotion.md; bound accepted base and preserve/change constraints |
| Multiple people or physique comparison | reference-hierarchy-and-canonical-locks.md; explicit unique subject roster and relative build/proportion constraints |
| Action/contact/load | source-production-design.md; pose-anatomy-contact-and-load.md; camera-body-equipment-alignment.md; weighted-load-and-proportion-realism.md when weighted |

| Motion handoff | visual-to-motion-handoff.md; collaborative-source-sequence-handoff.md only for actual collaboration |

Read every applicable branch. Single stills and group photographs are valid visual
tasks without being sequences. Branch selection is semantic; short Burmese
continuations retain the current task/mode unless the Creator materially changes it.

## Subject and reference admission

Give each depicted person a unique slot and intended identity. Declare instance
count; a canonical person normally has one instance unless the scene explicitly
requires otherwise. Keep peer identities and builds distinct. Bind every required
canonical role to that subject's actual image input. An attached group image must
state which slot it controls; do not spread one person's face/physique across peers.

Resolve accepted private policy and pixel versions from their current owner; text
and a directory listing are not pixel conditioning. Use compatible angle references
and the smallest sufficient set. Preserve height impression, frame, muscularity,
definition and grooming as separate dimensions. Evaluate comparative proportions
against accepted pixels rather than inventing a numeric aesthetic threshold.

`scripts/visual_execution_check.py` checks declared roster, reference bindings and
requested count. It does not detect duplicate people or judge physique in pixels.

## Tool and output boundary

Inspect supported image/edit controls. Do not promise masks, pose locks, output
counts or hidden review staging unless the current surface supports them. One call
may be used for multiple standalone outputs only when supported; inspect actual
returned count and layout. A collage does not fulfill separate-image delivery.

If the tool auto-displays results, classify them as auto-displayed/unreviewed until
pixel inspection; do not claim they were screened before the Creator saw them.
Failing outputs remain failed candidates and never become canon merely by display.

After rendering, inspect count/uniqueness, identity, physique/proportions, grooming,
anatomy/contact, edit preservation and relevant scene state. Mark not-observable
checks unknown; they cannot silently pass. Separate plan, observation and acceptance.

One initial failure permits one targeted correction. If the same structural defect
remains, change staging, view, reference selection or decomposition before rendering
again. This is not automatic retry authority for an unknown tool outcome.
