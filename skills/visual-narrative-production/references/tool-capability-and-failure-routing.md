# Tool Capability and Failure Routing

## Choose control from the actual execution surface

Before claiming reference, layout, or edit control, inspect the current tool's accepted inputs. Distinguish:
- identity/style image reference: conditions appearance but can also leak pose/composition;
- edit target: preserves part of a chosen base when locality is supported;
- structural guide (pose, depth, edge, layout, mask, 3D scene): constrains geometry only when the provider actually supports that input;
- text instruction: expresses intent but cannot guarantee exact contact or spatial placement.

Assign one role to each input. For a recurring subject, retain authoritative identity/physique pixels while using a separate geometry guide only if supported. A prior scene frame may guide continuity, but it must not silently turn into a copied composition or replace identity authority. Do not label text-only control as a pose lock.

## Route the observed failure

| Observed render failure | First correction | Escalate when it repeats |
| --- | --- | --- |
| Wrong character/proportions | Check actual pixel binding, reference angle, and role conflict | Remove competing style/action references; choose a compatible identity-preserving execution mode |
| Wrong geography or duplicated composition | Re-map camera axis, landmark visibility, and scene state | Use a simple spatial guide if supported; generate a new shot rather than editing a contradictory base |
| Wrong contact, body mechanics, or object intersection | Widen/reframe to expose contact chain; specify phase and support relation | Use a structural guide if supported, or choose a different readable moment/camera; do not retry the same text endlessly |
| Correct image with one local defect | Edit only the defective region/relationship when locality is supported | Regenerate if edits inherit impossible geometry or spill into identity/state |
| Repetitive successive shots | Change beat, action phase, camera relation, or new information | Re-plan coverage before further rendering |
| Incorrect performance/aftermath | Specify posture, breath, gaze, gesture, and intensity appropriate to character/state | Return to the narrative beat and accepted character baseline |
| Creator cannot inspect outputs | Use individual assets in requested review location | Read back the destination and repair delivery before requesting assessment |

After one failed targeted correction of a structural defect, stop repeating substantially identical prompts. Revisit the shot card, input authority, or execution capability. Record the failure class and the new strategy; a small purposeful alternative set may be more useful than a serial blind retry.

## Honest limits

Pixel QA is required even when a structural input is used. Tool availability and an accepted generation request prove neither fidelity nor correctness. If the current tool cannot represent a necessary spatial constraint, choose a less ambiguous shot or disclose the limitation and keep the result exploratory.
